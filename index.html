E-COMMERCE SYSTEMS • AI-ASSISTED BOOK LISTINGS • HUMAN REVIEW

Verity

Verity is an e-commerce operations project I'm developing to make book-listing work more manageable. It connects the practical problems of catalog accuracy, source research, and product copy with a clear process for reviewing suggested changes before they're accepted.

Its existing workflows can look up books by title, author, or ISBN; compare editions; preserve selected-source information; and prepare local listing drafts with optional AI-assisted research and copy. The Hello Verity browser interface lets me inspect evidence, compare alternatives, and explicitly accept or reject suggestions. Confirmed decisions are saved locally with revision history.

I helped shape the experience around real e-commerce tasks: compact review screens, understandable source information, and safeguards that prevent an outdated browser window from overwriting a newer decision.

Verity is a local prototype, not a production-deployed Shopify app. Its browser review saves decisions locally; it does not publish book listings or update a live store.

Screenshots show authored demonstration records, not production customer data or new independent bibliographic verification.

From book lookup to a reviewed listing

  1. Find the bookSearch by title, author, or ISBN in the existing operator workflow.
  2. Select the editionCompare available matches and save the selected preview without silently changing its identity.
  3. Prepare suggested contentResearch available metadata and prepare description or SEO suggestions, with AI only when explicitly requested.
  4. Inspect supporting evidenceSee the retained source, its limitations, and whether it describes the work or a specific edition.
  5. Review alternativesUse Hello Verity to expand fields, inspect choices, and stage Accept or Reject decisions.
  6. Save decisions locallyReview the proposed changes, confirm one local save, and preserve earlier revisions.

Lookup and AI enrichment are existing operator-run workflows; the browser currently handles saved-listing review. Nothing in this sequence automatically publishes to Shopify.

The problem

Listing a book online can involve edition matching, inconsistent metadata, descriptions, SEO fields, and decisions about what information is trustworthy enough to use.

I wanted to explore how AI could help with the preparation work without removing the need for source checks and human judgment.

My role

I defined the e-commerce problems, shaped feature requirements, directed iterative implementation with Codex, reviewed proposed workflows, and tested the application on Windows.

Much of my focus was on usability: helping someone understand the evidence, compare alternatives, and save decisions without needing to interpret technical records or command-line output.

What works today

  • Book lookup, edition comparison, and saved listing previews.
  • Optional AI-assisted preparation of book metadata, descriptions, and SEO suggestions.
  • Retained evidence with work-level versus edition-level distinctions and visible gaps.
  • A local browser interface with compact field accordions and reviewable alternatives.
  • Staged Accept/Reject decisions, explicit confirmation, and persistent local revision history.
  • Separate earlier Shopify development-store and ClickUp proposal/handoff workflows.

Safeguards and testing

  • Accepting content locally does not independently verify it or publish it to Shopify.
  • Source provenance, selected-edition identity, prior decisions, and rejected alternatives are retained.
  • Fingerprint checks help prevent stale browser windows from overwriting newer saved work.
  • Native Windows testing exercised local saves, reopening decisions, and a stale-window rejection.
  • Offline test fixtures and browser smoke checks are separate from live external-provider validation.

Tools and approach

The project uses TypeScript, Node.js, structured validation, local file persistence, and opt-in AI workflows. Earlier development integrations include Shopify and ClickUp APIs.

Implementation has been built with Codex assistance. I have directed requirements, evaluated tradeoffs, tested functionality, and refined how the operator experience should work.

Where I'm taking it

Next steps include editing saved suggestions directly in the browser and adding a conversation interface that uses the same reviewed records and workflows. Broader catalog and website maintenance features are also part of the longer-term vision.

These are planned capabilities, not a claim that Verity is conversational, cloud-hosted, or managing a production store today.

The project repository is private. Screenshots use disposable demo fixtures. This case study documents a locally tested development project, not a production deployment or measured sales improvement.
