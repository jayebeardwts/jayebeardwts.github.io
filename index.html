AI WORKFLOWS • SHOPIFY • CLICKUP • HUMAN REVIEW

Shopify × ClickUp AI Product Workflow

I wanted to see how AI could help with Shopify product-description requests without losing track of the right product, its facts, or the person approving the change.

With Codex assistance, I designed and tested a workflow that starts with a ClickUp task, prepares a reviewable description proposal, records a human decision, and sends an approved handoff back to ClickUp. It also supports a separately confirmed description update to one draft product in a Shopify development store.

From request to reviewed change

  1. Start with ClickUp Select a specific development task and its writing request.
  2. Find the Shopify product Match the exact product ID; don't guess by title.
  3. Generate a proposal Suggest a description using the retrieved product facts.
  4. Check the content Validate the response and flag selected unsupported claims.
  5. Review the exact text Save the proposal and explicitly approve or reject it locally.
  6. Send the ClickUp handoff Confirm a comment to the original task and record its outcome.
  7. Confirm the Shopify update Separate authorization for one draft product, description only.

Why I built it

Product-description updates can involve more than writing new copy. Someone needs to find the right item, check the facts, review the wording, and make sure the approved version is the one delivered.

I wanted to explore where AI could help without skipping those steps.

My role

I brought my Shopify operations experience into the project: defining requirements, directing implementation with Codex, testing the workflow, and refining the approval and handoff steps.

I focused on the practical questions: what does the reviewer need to see, what should stop an update, and what happens if a request fails?

What works today

  • Read-only matching between a development ClickUp task and the correct Shopify product ID.
  • Mock or opt-in AI description generation, with saved proposed text and a clear explanation.
  • Local human approval or rejection tied to the exact saved proposal.
  • Separately confirmed delivery of the approved proposal as a ClickUp task comment.
  • A controlled, description-only update for one draft development-store product.

Safeguards and testing

  • New proposals always begin pending; generating text never approves it.
  • Validation looks for selected unsupported product details, with at most one corrective AI revision.
  • Fresh source checks help catch changes between approval, handoff, and update.
  • Delivery and update receipts block repeat attempts; uncertain results require reconciliation.
  • Offline tests use simulated service responses, and real writes are limited to the development environment.

Tools and approach

The prototype uses TypeScript, Node.js, the OpenAI Agents SDK, Shopify and ClickUp APIs, and Zod for structured validation. Vitest exercises the workflow with simulated service responses.

The code was developed with Codex assistance. My contribution was translating e-commerce needs into requirements, reviewing the implementation, testing the behavior, and deciding how the system should handle approvals and failures.

Where I'd take it next

I'd like to bring review and feedback directly into ClickUp so someone could request a revision without switching to the local app. I could also see the approach supporting Shopify theme tasks and, eventually, content platforms such as Storyblok, Sanity, and Craft.

Those are ideas for future work, not completed features. The current prototype still requires operator review and is not a production system.

The source repository is private. This case study describes a development experiment, not a production deployment or a measured business result.
